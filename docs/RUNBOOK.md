# Запуск и демонстрация

**Сначала настройте Supabase:** [инструкция миграции](SUPABASE.md). Новый запуск по умолчанию требует `DATABASE_URL` и выполненный SQL-импорт. Все учётные записи сохраняются. Инструкции ниже о первом создании CSV и `state.lock` относятся только к явно выбранному `STORAGE_BACKEND=csv`.

Требования: Node.js 22+ / npm, Go 1.25+. В текущем рабочем каталоге Go 1.27.1 уже установлен в игнорируемую `.tools/go`; установщик был проверен по SHA-256 из go.dev. На другой машине установите Go с https://go.dev/dl/ . Порты 3000 и 8080 должны быть свободны.

Из корня проекта:

```sh
npm start
```

Команда установит frontend-зависимости, если их нет, соберёт Go, создаст CSV-хранилище при первом запуске и запустит API и Next.js. Откройте http://localhost:3000 . На первом старте нужен интернет только для npm-зависимостей; рабочие данные остаются локально. Ctrl+C останавливает оба процесса. Launcher удаляет только lock, принадлежащий своему Go-процессу. После аварийного завершения убедитесь, что другого экземпляра нет, прежде чем вручную удалять `data/state.lock`.

## Учётные записи

Логины: `employee` (E0002), `manager` (E0175 — непосредственный руководитель), `hr`, `colleague` (E0001, другой сотрудник). Пароль сгенерирован и записан в `data/demo-accounts.txt`, который исключён из Git. Не помещайте его в исходный код. Можно заранее задать DEMO_PASSWORD в локальном .env; это применяется только при первом создании state.csv. HR выдаёт дальнейшие учётные записи через «Доступ и данные»; публичной саморегистрации в корпоративном контуре нет.

1. Войти employee → «Мой маршрут» → раскрыть основания → «Выбрать шаг» → выбрать дату → явно отправить руководителю.
2. Выйти, войти manager → «Заявки и решения» → «Согласовать» → подтвердить. Альтернатива — отказ с причиной.
3. employee → «Мои шаги» → «Отправить результат» → описать проверяемую демонстрационную работу (20+ символов).
4. hr → «Заявки и решения» → проверить текст → «Подтвердить результат» и основание (8+ символов). Можно вернуть на доработку.
5. employee → обновить → увидеть рост навыков/процента и журнал. Текущий грейд не меняется автоматически.

Уже выполненная проверочная цепочка сохранена в рабочем state.csv; исходный demo.csv не менялся. Участие во внешнем курсе самим приложением не подтверждается. Для демонстрации HR может принять учебный результат до указанной будущей даты; это ограничение прототипа.

## Дополнительные профили

HR → «Доступ и данные»: выбрать employees.json и activity_history.csv, подтвердить импорт. Поддерживается объект `{meta,employees:[...]}` или массив employees, история — строго с исходными 10 CSV-колонками. Примеры в `fixtures/`: критичный навык против самого слабого, отсутствие prerequisites, полностью достигнутая цель. Генератор: `node scripts/create-jury-fixtures.mjs`. Дубликаты ID и неверные ссылки не меняют хранилище. После импорта выдайте профилю доступ.

## Gemini

Скопируйте .env.example в .env. Модель жёстко задана: gemini-3.8-flash. GEMINI_API_KEY только на сервере; никакого NEXT_PUBLIC ключа нет. Без ключа API возвращает 503 и UI честно сообщает об отсутствии ИИ. При ALLOW_EXTERNAL_AI=false также 503. Исходные данные хакатона запрещено передавать наружу — оставьте false. Для собственных разрешённых синтетических данных включение требует `ALLOW_EXTERNAL_AI=true`, ключа и перезапуска. После этого сам пользователь подтверждает запрос обезличенного контекста в интерфейсе. Ошибки и время ожидания не подменяются готовым ответом.

Реальная модель в этой сессии не вызывалась. Положительный и отрицательные контракты проверены только через Go httptest-сервер; тестовый ответ не показывается в рабочем приложении.

## Проверки и production

```sh
npm test
npm run build
```

`npm test` запускает Go-проверки, `npm run build` проверяет TypeScript и собирает Next.js. Для запуска собранной версии установите `NODE_ENV=production` и выполните `npm start` (PowerShell: `$env:NODE_ENV='production'; npm start`). Backend остаётся Go. Build-time proxy по умолчанию идёт на 8080; при изменении порта задавайте API_PORT и при сборке.

Раздельно: `go -C backend run .` запускать из корня с правильным DATASET_DIR (используйте абсолютный путь к корню) и DATA_DIR; проще запускать собранный `backend/careerquest.exe` / `backend/careerquest` из корня. Frontend: `npm --prefix frontend run dev`.

Не запускайте несколько writer-процессов. Для независимой проверки используйте другой DATA_DIR и PORT. Каталог DATA_DIR должен быть локальным диском; сетевые файловые системы и синхронизируемые папки не проверены.
