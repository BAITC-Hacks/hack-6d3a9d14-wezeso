# Архитектура

```
Браузер → Next.js /api proxy → Go API → CSV snapshot
                                └→ Gemini generateContent (опционально)
```

Next.js 16 / React 19 / TypeScript: одна рабочая область с действующими разделами. Kumo Button, Input, Badge; Phosphor; локальные Manrope 400/500/600/700. bloub BotEngine — оригинальный чистый TypeScript, React управляет SVG, состоянием и часами; кадры до 30 fps, при скрытой вкладке расчёт кадров приостанавливается, reduced-motion статичен. Зелёное плоское тело, без орбит/градиентов оригинальной Vue-оболочки.

Go 1.25+: net/http, стандартная библиотека, без БД и сторонних серверных зависимостей. Backend слушает loopback 8080, Next.js loopback 3000; браузер обращается к одному origin. Обработка ролей исключительно на сервере, пользователь не может передать желаемую роль в команду.

## CSV и транзакции

`data/demo.csv` содержит 3075 строк объектов + заголовок: 200 employee, 40 event, 60 skill, 32 role, 2743 history. Формат `kind,id,payload`; payload — JSON внутри CSV-ячейки с корректным экранированием encoding/csv. Так сохраняются карты навыков и исходная схема без потери типов. `data/state.csv` — рабочий CSV того же формата, дополнительно user/request/audit/recommendation. Пользователи хранятся строками kind=user со стойкими хешами, не открытыми паролями. Импорт JSON/CSV исходного формата через HR преобразуется в эти записи.

Одна транзакция: mutex → глубокая копия состояния → проверка команды → изменение + audit → временный CSV в том же каталоге → fsync → atomic replace (Windows MoveFileExW с REPLACE_EXISTING/WRITE_THROUGH; Unix rename + fsync каталога) → замена состояния в памяти. При ошибке записи успех не возвращается и состояние памяти не изменяется. Один state.lock исключает второй writer; это не распределённая блокировка. Файл формируется целиком на каждую команду. Идентификаторы импорта ограничены безопасным алфавитом, пользовательские строки находятся в JSON-ячейках, а не формульных ячейках CSV.

История завершений после last_review_date применяется в хронологическом порядке. Сначала считаются исходные навыки и история; затем сохранённые дельты подтверждённых заявок. Повторное завершение запрещено, кроме EV_036, для заявок действует проверка текущего этапа. Одновременные подтверждения сериализуются: одно успешно, второе получает 409. Для каждой дельты действует `max(old, min(5, max_level, old + gain)) - old`.

## Подбор и Gemini

Фильтры: добровольность, текущая роль/грейд, prerequisites, будущая сессия или self_paced, отсутствие уже завершённой/текущей активности и отказа. Затем оценка: за закрываемый уровень критичного навыка +12, другого целевого навыка +4; похожий пропуск/отказ −2, повторный по самой активности −3; каждый час −0.15; каждая текущая активность −0.2; удалённый сотрудник + очный формат −4. Это прозрачная эвристика, а не модель. Фактор текущей общей нагрузки одинаков для кандидатов и не меняет их взаимный порядок; его цель — показать нагрузку в обосновании, а не искусственно заявлять влияние на ранжирование. При равном балле порядок детерминирован по event_id. Нет публичных рейтингов людей.

Gemini получает допустимых кандидатов, числовые уровни/требования и агрегированные факты истории, без имени, employee_id, логина и raw-истории. Модель ровно `gemini-3.8-flash`; ключ только из GEMINI_API_KEY в заголовке x-goog-api-key. ALLOW_EXTERNAL_AI должен быть true исключительно для разрешённых к передаче данных. JSON-схема, 1–3 различных event_id из allowlist, ненулевое объяснение и неизвестные проверяются повторно. Общий deadline 9 секунд. 4xx/5xx, блокировка, отсутствие текста, неверный JSON, запрещённое событие и timeout не создают рекомендацию. Успех сохраняет ответ модели отдельно от снимка проверенных оснований. Если контекст изменился во время запроса, 409. Ни одна рекомендация не создаёт заявку автоматически.

## Доступ

Employee: только собственный профиль, цель, подбор, заявки и журнал. Manager: своё пространство и профили прямых подчинённых через manager_id; согласование только подчинённым. HR: сводка, проверка результата, импорт и выдача employee/manager доступа (manager только для Lead). HR-доступ не выдаётся через форму.

PBKDF2-HMAC-SHA256, 600 000 итераций, случайная 128-битная соль на хеш. Случайный 192-битный session token, в памяти индекс по SHA-256, HttpOnly / SameSite=Strict / 8 часов; Secure включается настройкой для HTTPS. CSRF-token + проверка Origin на mutation, лимит тела 4 МБ, ограничение попыток входа, таймауты сервера. Сессии намеренно не переживают перезапуск. Исходный state.csv и локальный файл доступа исключены из Git. Не хранить реальную персональную информацию в этом прототипе.

## Границы

Нет LMS, SSO, писем, банковских операций, календаря, внешней проверки сертификатов, контента учебных курсов и автоматического повышения. HR подтверждает текстовое демонстрационное доказательство; прототип допускает демонстрацию результата до календарной даты будущей сессии, не проверяет факт проведения. Интерфейс русский, названия/описания каталога остаются английскими из датасета; полной локализации kk/ru нет. Сигнал отсутствия активности не является прогнозом увольнения.
